# 0005. 연도가 아니라 회차(edition)를 단위로 한다

- 상태: 확정
- 날짜: 2026-11-01

## 맥락

처음 구조는 "1년에 설문 하나"를 전제로 연도(`year`)를 키로 썼다. 앞으로 프론트엔드·백엔드·DevOps 같은 트랙별 설문이나, 한 해에 여러 번 하는 분기 설문을 할 수 있다. 그러면 주소, DB, 문항 파일이 모두 연도 하나로는 구분되지 않는다. 오픈 전이고 응답이 0건이라 지금 바꾸는 비용이 가장 작다.

## 결정

- 한 번 열고 닫는 설문 하나를 **회차**라 부르고, 문자열 ID 로 구분한다: `2026`(연례), `2027-q1`(분기), `2027-frontend`(트랙), `2025`(결과 화면 시험용 예시).
- 회차 목록은 `src/editions.ts` 한 곳에 둔다. 제목, 마감 시각, 설문·유형 결과 유무, 예시 여부를 적는다.
- 문항은 회차마다 `questions/<회차>.yaml`, 집계 결과는 `src/results/<회차>.json`, DB 는 `responses.edition`.
- 주소는 `/<회차>/survey`, `/<회차>/type/<유형>`, `/<회차>/results`. 홍보용 짧은 주소 `/survey`, `/results` 는 지금 열린 회차와 가장 최근 결과로 보낸다.
- 회차끼리 비교할 수 있게, **같은 문항 `id` 는 모든 회차에서 같은 선택지 `code`** 를 쓴다. 테스트로 막는다.

## 검토한 대안

- **연도를 그대로 두고 트랙·분기를 연도 아래 경로로:** `/2027/frontend/survey` 처럼 깊어지고, DB 와 문항 파일에 연도 말고 두 번째 키가 따로 필요하다.
- **트랙마다 별도 설문을 같은 시기에:** 응답자가 나뉘어 공통 문항의 표본이 작아진다. 같은 시기라면 연례 설문 안에서 `role` 문항으로 분기한다. 별도 트랙 회차는 시기와 목적이 다를 때만 쓴다.
- **분기마다 연례와 같은 길이로:** 응답 피로가 크다. 분기 회차는 5~10문항의 짧은 설문으로 몇 가지 지표의 변화만 본다.

## 결과

- 연례 설문은 `2026` 이라는 회차 하나일 뿐이라, 지금 주소 모양은 거의 바뀌지 않는다.
- 마감 검사는 "이 회차가 지금 열려 있는가"로 바뀌어, 회차가 여럿이어도 그대로 동작한다.
- 예시 회차 `2025` 는 오픈 전에 지운다(AGENTS.md 오픈 체크리스트).
