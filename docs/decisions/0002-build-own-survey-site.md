# 0002. 설문 사이트를 직접 만든다

- 상태: 확정
- 날짜: 2026-10-31

## 맥락

1회차는 2026년 11월 오픈, 12월 발표다. [설문 도구 조사](../research/2026-10-survey-tools.md)는 준비 기간이 2주뿐이라는 이유로 1회차에는 Tally를 쓰고 직접 구현은 미루자고 했다. 하지만 그 판단은 처음부터 만드는 경우를 전제로 했다. `DaleStudy/feedback`(feedback.dalestudy.com)에서 같은 스택과 문항 구조를 이미 운영해 가능성을 검증했다.

## 결정

1회차부터 설문 사이트를 직접 만든다. `feedback`의 스택(TanStack Start, Cloudflare Workers, D1 + Drizzle, daleui)과 문항 유형 구조를 바탕으로 한다.

## 검토한 대안

- **Tally:** 무료로 필요한 기능이 대부분 되고 준비가 빠르다. 하지만 응답 화면을 달레 UI로 만들 수 없고, 데이터 형식과 익명성 정책을 직접 통제할 수 없다. 2회차에 자체 플랫폼으로 옮기면 1회차와 데이터 형식을 다시 맞춰야 한다.
- **Google Forms:** 익명 응답이면 중복을 막을 수단이 없다.
- **`feedback` 앱에 설문을 추가:** `feedback`은 GitHub 로그인이 전제이고, 익명 모드는 비용이 커서 일부러 뺐다(`feedback`의 `AGENTS.md`). 응답자 모델이 정반대라 별도 저장소로 만든다.

## 결과

- **가져올 것:** 스택, 문항 유형 레지스트리 구조, 공통 문항 `key`로 설문 간 비교하는 방식, 배포 방식.
- **새로 설계할 것:** 로그인 없는 응답자 모델. 식별자 없이 중복·봇을 막는 방법(Turnstile, 브라우저 저장소의 무작위 ID), IP·User-Agent를 저장하지 않는 응답 저장, 만 14세 확인과 동의 화면.
- **국외 이전 고지는 그대로 필요하다.** D1 은 `apac` 위치 힌트만 주고 국내 저장을 보장하지 않는다. 동의 화면과 처리방침에 Cloudflare 와 저장 위치를 적는다([개인정보 조사](../research/2026-10-privacy-law.md)).
- **D1 쓰기 한도:** 무료 플랜은 하루 10만 행 쓰기다. 응답 1건을 1행(JSON)으로 저장하거나 유료 플랜($5/월)을 쓴다.
- **응답 화면을 달레 UI로 만들 수 있다.** [디자인 시안](https://claude.ai/artifact/NaFDDC64TD9oCkXTDBuPyh)이 1회차 화면의 기준이 된다.
- 일정 위험은 남는다. 문항 확정·검수와 개발이 같은 2주에 겹친다.
