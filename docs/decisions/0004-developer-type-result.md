# 0004. 응답을 마치면 개발자 유형을 보여 주고 공유하게 한다

- 상태: 확정
- 날짜: 2026-11-01

## 맥락

경품이 없어서([0001](0001-no-incentives.md)) 응답자가 10분을 쓸 이유는 12월의 결과 공개뿐이었다. 2026-11-01 운영진 데모에서 헬레나가 "응답자에게는 시간을 쓸 이유가 없다. 마지막에 가벼운 유형 결과를 보여 주고 공유하기를 넣자"고 했고, 에반이 "내년 개발 커리어 운세" 같은 재미 요소를 더했다. 첫해에는 자체 채널이 없어 응답자가 직접 퍼뜨려 주는 효과가 특히 필요하다([배포 채널 조사](../research/2026-10-distribution-channels.md)).

## 결정

2026년 설문부터 완료 화면에 개발자 유형과 2027년 커리어 한 줄을 보여 주고, 유형 페이지(`/type/<유형>`) 링크로 공유하게 한다.

- 유형은 고정 문항 두 개로만 정한다: `ai_frequency`(매일 / 가끔 / 안 씀) × `company_criteria` 에 `growth` 가 있는지. 6가지.
- 유형은 브라우저에서만 계산하고 서버에 저장하지 않는다. 공유 링크에는 유형 이름만 넣는다.
- 달레 UI 는 그대로 쓰고, 유형별 일러스트는 정적 이미지로 보완한다(에반의 병목 우려, 헬레나의 보완안).

## 검토한 대안

- **유형 없이 결과 공개만:** 보상이 12월에야 돌아오고, 공유할 거리가 없다.
- **유형을 서버에 저장:** 답에서 다시 계산할 수 있어 얻는 정보가 없고, 공유 링크와 응답을 잇는 단서만 생긴다.
- **유형 전용 문항 추가:** 문항 수가 늘고, 원하는 유형을 받으려고 답을 고르는 일이 생긴다. 이미 있는 문항으로 정하면 문항 화면에서 유형이 드러나지 않는다.

## 결과

- 응답자가 결과를 공유하면 `ref=share` 로 들어온다. 결과 리포트에서 이 경로를 따로 보여 주어, "테스트"로 들어온 응답이 결과를 얼마나 바꿨는지 밝힌다. (Superseded by [0009](0009-no-referral-tracking.md): 유입 경로를 수집하지 않는다)
- 유형 문구는 응답 데이터가 아니라서 해마다 바꿔도 연도별 비교에 영향이 없다.
