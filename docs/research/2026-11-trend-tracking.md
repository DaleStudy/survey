# 회차마다 트렌드를 보여 주기 위한 설계 검토 (2026-11-01)

2027년부터 상반기·하반기 두 번 설문하고, 회차마다 바뀌는 트렌드를 모아 보여 주려 한다. 회차 구조([ADR 0005](../decisions/0005-survey-editions.md))를 정한 뒤, 트렌드를 믿을 수 있게 보여 주려면 무엇이 필요한지 정리했다. 아직 결정이 아니다.

## 고려할 것

1. **고정 문항과 교체 문항을 나눈다.** 트렌드는 같은 문항을 같은 선택지로 여러 번 물어야 생긴다. `fixed: true` 문항이 뼈대다. 반기 회차가 짧아도 핵심 몇 개(AI 사용 빈도, 근무 형태, 구직 활동 등)는 매 회차 넣는다.
2. **선택지는 늘리되 뜻은 바꾸지 않는다.** 새 도구·언어는 새 code 를 더한다. code 를 다른 뜻으로 재사용하지 않는다. 빠진 선택지는 지우지 않고 은퇴 표시만 한다. 그러려면 선택지에 `since`(처음 들어간 회차)·`retired`(빠진 회차) 칸이 필요하다.
3. **"기타 (직접 입력)"로 새 트렌드를 먼저 발견한다.** 떠오르는 도구는 선택지에 없으니 직접 입력에서 먼저 보인다. 이번 회차 직접 입력에 많이 나온 것을 다음 회차 정식 선택지로 올린다. 지금은 "기타"를 골라도 입력 칸이 없다. 첫 회차부터 모아야 2027년 상반기에 쓸 수 있다. 직접 입력한 글은 자유 의견처럼 공개 전에 검토한다.
4. **응답자 구성이 바뀌면 가짜 트렌드가 생긴다.** 유입 채널에 따라 경력·직무 분포가 달라진다. 회차마다 응답자 구성(`ref`, 경력, 직무)을 함께 보여 주고, 중요한 지표는 같은 집단 안에서 비교한다(예: 현업 3~5년 차의 AI 사용 빈도). 익명이라 같은 사람을 잇지 못하므로 패널이 아니라 반복 단면 조사라고 밝힌다.
5. **계절 효과.** 상반기와 하반기는 채용 시즌, 연말 평가처럼 분위기가 다르다. 직전 회차뿐 아니라 전년 같은 반기와도 비교한다.
6. **화면.** 결과 페이지 고정 문항에 "지난 회차 대비" 변화를 붙이고, `/trends` 에 핵심 지표의 회차별 선 그래프를 둔다. 회차별 집계 JSON 을 문항 `id`·`code` 로 이어 붙이면 되므로 DB 를 다시 볼 필요는 없다.

## 언제 할지 (제안)

| 시기 | 할 일 |
|---|---|
| 2026년 오픈 전 | "기타" 선택지에 직접 입력 칸. 응답에 함께 저장하고 공개 CSV 에서는 뺀다 |
| 2026년 결과 발표 | 응답자 구성(경로, 경력, 직무)을 결과에 표시 |
| 2027년 상반기 준비 | 선택지 `since`·`retired`, 반기 회차 문항 구성, "지난 회차 대비", `/trends` |
